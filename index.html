What should my Excel file look like?

Sheet "Project" (label in column A, value in column B): Project Name, Currency, Data Date, Original Contract Value, Original Cost Budget (without contingency and reserve), Contingency Budget, Management Reserve, Percent Complete. Optional: Pending Older Than (days), Burn Index Amber, Burn Index Red, Blank Likelihood Counts As.

Sheet "Changes" (one row per change, column names like a typical ERP export): WBS Element, Notification (change / claim number), Description, Funding (Client / Contingency / Management Reserve), User Status (Pending / Approved / Rejected / Withdrawn), Amount (cost impact), Client Price, Probability, Schedule Impact (days), Created On, Decision Date. Optional: Currency, Person Responsible, Notes.

From your ERP (SAP or others): export your change or claim list to Excel and paste it into the Changes sheet. From any other source: fill in the same sheet from a change register or spreadsheet. Take Percent Complete from your schedule, for example Primavera P6. Your own column names work too – for example Change ID, Status, Cost Impact, Likelihood, Date Raised. Dates like 28.8.2026 are read day-first; decimals with a comma (0,45) work.

Notes on your data the tool made these assumptions

    How is it calculated?
    • Contingency left today = Contingency Budget − approved Contingency changes. Savings (negative cost) give money back.
    • Left after likely pending = Contingency left today − (cost × likelihood) of every pending Contingency change. Empty likelihood counts at 100% by default (conservative).
    • Burn index = % of contingency used ÷ % complete. 1.00× means contingency is used at the same pace as progress. Amber and red limits (default 1.00× and 1.25×) are my rule of thumb and can be changed on the Project sheet. Early in a project (engineering, procurement, ground works) contingency is often used faster than progress, so read the index together with the project stage and the risks that are still open.
    • If today's rate continues is a simple straight line: contingency used ÷ % complete. It is a warning sign, not a forecast – a proper forecast compares the remaining contingency with the open risks in your risk register (for example with a Monte Carlo analysis).
    • Status light: red if approved or approved + likely pending changes are larger than the contingency budget, or the burn index is above the red limit; amber if the burn index is above the amber limit or the straight-line projection runs out before completion; otherwise green.
    • Client change orders change the contract value (Client Price) and the cost budget (Cost Impact). They do not use contingency. Margin = Client Price − Cost Impact.
    • Schedule impact is a simple sum of the days in the log. Delays on different paths do not add up, so this is not a critical-path analysis.
    • Rejected and Withdrawn changes are listed but not counted. Pending changes older than the limit (default 30 days) are listed under Decisions needed.
